# inmc-urb — 얼티메이트 랜덤박스

**맵 곳곳에 보급상자를 떨어뜨리고, 플레이어가 그것을 찾아가서 여는** 배틀로얄식 에어드랍 플러그인입니다.

관리자는 상자 하나를 만들어 **보상 · 확률 · 등장 위치 · 등장 시간대 · 오픈 조건 · 연출**을 전부 인게임 GUI에서 정합니다. 정해진 주기가 되면 상자가 월드 어딘가에 나타나고, 좌표가 채팅으로 공지됩니다. 공지의 **[추적하기]** 를 누르면 나침반이 그 상자를 가리키고 보스바에 남은 거리가 뜹니다. 도착해서 상자를 우클릭하면 3초간 여는 연출이 흐르고 — 움직이면 취소됩니다 — 보상이 룰렛으로 돌다가 결과에 멈춥니다.

로비에 영구 설치해두고 "한 사람당 평생 한 번, 열쇠가 있어야 열리는" 상자로 쓸 수도 있고, 반대로 `/urb search` 목록에서 빼고 추적도 막아 **아는 사람만 찾을 수 있는 숨겨진 상자**로 둘 수도 있습니다.

설정을 다 마친 뒤에는 **실제 추첨기를 그대로 돌리는 시뮬레이터**로 "1만 번 열면 이 아이템이 몇 번 나오는가"를 미리 확인하고, 운영을 시작한 뒤에는 **통계 화면**에서 설정 확률과 실제 출현률을 나란히 비교할 수 있습니다.

`UltimateRandomBox` 를 Paper 26.2 / Java 25 / Kotlin 으로 새로 작성했으며, **외부 플러그인 의존이 하나도 없습니다.** (같은 묶음으로 배포되는 `inmc-core` 는 함께 넣어야 합니다 — Kotlin 런타임과 공용 프레임워크가 거기 들어 있습니다.)

## 요구 사항

| 항목 | 값 |
|---|---|
| 서버 | Paper **26.2** 이상 |
| Java | **25** |
| 필수 의존성 | **`inmc-core`** — 같이 배포되는 공용 런타임입니다. 이것 하나뿐이며, 이것 없이는 로드되지 않습니다. |
| 선택 연동 | Vault(돈) · PlaceholderAPI · MMOItems/MythicLib · WorldGuard · Lands · ItemsAdder/Nexo/Oraxen/EcoItems |

선택 연동은 전부 없어도 정상 부팅·동작합니다. 없으면 해당 기능만 조용히 비활성화됩니다. 연동 플러그인이 우리보다 늦게 켜져도 자동으로 다시 인식합니다.

## 빌드

```bash
./gradlew build
```

`build/libs/inmc-urb-1.0.0.jar` 를 `plugins/` 에 넣으면 됩니다. (`-dev.jar` 은 셰이딩 전 파일이니 사용하지 마세요.)

## 테스트 서버

```bash
./gradlew runServer
```

Paper 26.2 를 자동으로 받아 `run/` 에서 띄우고 방금 빌드한 jar 을 설치합니다. **최초 1회는** 서버가 EULA 를 요구하며 종료되므로, `run/eula.txt` 를 열어 `eula=true` 로 바꾼 뒤 다시 실행하세요. (마인크래프트 EULA 동의는 서버 운영자가 직접 해야 하는 것이라 빌드에서 자동으로 처리하지 않습니다.)

연동 플러그인을 함께 시험하려면 해당 jar 을 `run/plugins/` 에 넣으면 됩니다.

## 명령어

권한은 **`urb.admin` 하나뿐**입니다. 아래 유저용 명령어는 권한이 필요 없습니다.

### 관리자 (`urb.admin`)

| 명령어 | 설명 |
|---|---|
| `/urb` | 상자 목록 GUI |
| `/urb create <이름>` | 상자 생성 (`boxes/<이름>.yml` 생성) |
| `/urb copy <원본> <새이름>` | 설정·보상까지 그대로 복제 |
| `/urb remove <이름>` | 상자 삭제 |
| `/urb remove all` | 전체 삭제 (확인 창이 뜹니다) |
| `/urb spawn <이름>` | 상자 설정대로 소환 |
| `/urb spawnnow <이름>` | 내가 선 위치에 즉시 소환 (최대 개수 무시) |
| `/urb open <이름>` | 명령어로 열기 — 열쇠·돈은 소모되지만 오픈 메시지는 나오지 않습니다 |
| `/urb reset <이름>` / `/urb reset all` | 소환된 상자 회수 (원래 블록으로 복원) |
| `/urb testarea <이름>` | 생성 위치를 200곳 뽑아 **실제로 놓일 수 있는지** 시험 |
| `/urb simulate <이름>` | 보상 확률 시뮬레이션 |
| `/urb stats [이름]` | 실제 오픈 통계 (인자 없으면 전체 오픈 기록) |
| `/urb log` | 최근 오픈 기록 |
| `/urb reload` | 설정 다시 읽기 |

### 유저

| 명령어 | 설명 |
|---|---|
| `/urb info [상자]` | 확률표 GUI. 인자 없이 쓰면 상자 선택 창 |
| `/urb search` | 생성된 상자 위치 검색 (`search.cooldown` 주기 제한) |
| `/urb track` | `/urb search` 와 동일 |
| `/urb untrack` | 추적 중지 |
| `/urb notice` | 당첨 공지 확인창 |
| `/urb ranking` | 상자를 가장 많이 연 플레이어 순위 |

검색 결과에서 상자를 클릭하면 나침반이 그쪽을 가리키고, **보스바**에 남은 거리와 진행도가 표시됩니다. 등장 공지의 `[추적하기]` 버튼은 내부적으로 `/urb trackto <월드> <x> <z>` 를 실행합니다.

> **왜 액션바가 아니라 보스바인가** — 액션바는 HUD 플러그인(BetterHud 등)이 매 틱 다시 그리는 영역이라, 그런 플러그인이 깔린 서버에서는 우리 글자가 즉시 덮여 보이지 않습니다. 보스바는 우리 것이고 다른 플러그인의 바와도 겹치지 않게 쌓이며, 진행률을 문자로 흉내 내지 않고 그대로 표시할 수 있습니다.

## 동작 방식에서 알아둘 것

### 내용물 추첨

등록된 아이템은 **각자 독립적으로** 추첨됩니다. 당첨된 것 중 `max-rolls` 개까지만 지급되고, 하나도 당첨되지 않으면 확률 가중치로 `min-rolls` 개를 채웁니다. 같은 아이템이 한 번에 두 번 나오는 일은 없습니다.

> 54개를 등록하고 최대 2개로 설정하면 결과는 **1~2개**입니다. 확률이 높으면 거의 항상 2개, 낮으면 1개가 나옵니다. 최대 54로 두면 확률에 따라 1개부터 54개까지 나옵니다.

내용물은 6×9 창의 **무작위 칸**에 배치됩니다.

### 보상 티어

기본적으로 모든 보상은 **하나의 배출 개수 범위를 두고 경쟁**합니다. 그래서 희귀템의 확률만 올리면 일반템이 밀려나고, 최대 개수를 올리면 전체 배출량이 같이 늘어납니다. "일반 2개는 확정으로 주고, 희귀는 가끔 하나 더" 를 표현할 방법이 없습니다.

**티어**는 보상을 여러 풀로 나누고 풀마다 따로 추첨합니다.

| 풀 | 보상 | 배출 |
|---|---|---|
| 기본 풀 | 철·석탄·빵… | 2 ~ 2개 |
| `희귀` | 다이아·네더라이트 | 0 ~ 1개 |

이렇게 두면 매번 일반템 2개가 확정으로 나오고, 희귀 풀은 자기 확률대로 0개나 1개를 얹습니다. 서로 자리를 뺏지 않습니다.

- 티어를 하나도 만들지 않으면 **예전과 완전히 동일하게** 동작합니다 (풀이 1개인 경우)
- `min-rolls: 0` 인 티어는 아무것도 안 나올 수 있습니다
- 티어를 지우면 그 보상들은 삭제되지 않고 **기본 풀로 돌아갑니다**
- ⑨ 화면의 **합산 예측**이 모든 풀을 합친 개수 분포를 즉시 계산해 보여줍니다

### 생성 시간대

⑩ 에서 요일과 시간을 지정하면 **자동 생성**이 그 창 안에서만 일어납니다. `/urb spawn`, `/urb spawnnow`, 캡슐 오픈은 시간대와 무관하게 항상 동작합니다 — 관리자가 손으로 놓는 것을 스케줄이 막으면 그냥 고장 난 것처럼 보이기 때문입니다.

종료 시각이 시작보다 이르면 자정을 넘겨 이어집니다 (`22:00 ~ 02:00` = 저녁 이벤트). 시간대 밖에서도 주기 타이머는 계속 돌기 때문에, 창이 열리는 순간 밀린 물량이 한꺼번에 쏟아지지 않습니다.

### 스폰 위치

흙 속·공중·물 위·용암 위·나무 꼭대기에는 생성되지 않습니다. 지면을 찾을 때 나뭇잎을 무시하기 때문에, 숲에서도 캐노피 위가 아니라 나무 아래 땅에 놓입니다. 랜덤 영역 모드에서는 꽃이나 양탄자를 부수지 않고(진짜 빈 칸만 사용), 특정 좌표 모드에서는 지정 위치의 블록을 치우고 배치합니다. 동굴 스폰은 상자별로 켜고 끌 수 있습니다(기본 꺼짐).

랜덤 영역은 **사각형**(두 코너)과 **원형**(중심+반지름) 중에 고를 수 있습니다. 원형은 면적 기준으로 고르게 뿌려지므로 중심에 몰리지 않습니다.

`/urb testarea <상자>` 는 실제로 상자를 놓지 않고 후보 좌표 200곳을 뽑아 결과를 알려줍니다.

```
[ 랜덤박스 ] 보급 상자 생성 위치 200곳을 시험했습니다.
· 청크 로드됨: 43 / 미로드: 157  (미로드는 대기열로 들어갑니다)
· 배치 가능: 9 (20.93%)
· 지면 없음(물·용암·동굴 등): 34
[ 랜덤박스 ] 절반 이상이 실패합니다. 영역을 옮기거나 Y 범위를 넓혀보세요.
```

영역이 통째로 바다이거나 전부 보호구역인 경우를 **"상자가 안 나오는데요"** 로 발견하는 대신 여기서 바로 알 수 있습니다. 청크를 강제로 로드하지 않으므로 실행 자체는 서버에 부담이 없습니다.

### 생성 방식

| 방식 | 동작 |
|---|---|
| `RANDOM_AREA` | 지정한 영역(사각형/원형) 안의 랜덤 위치 |
| `FIXED_POINTS` | 등록된 좌표 중 하나에 주기적으로 생성 |
| `PERMANENT` | 등록된 **모든** 좌표에 영구 설치. 소멸하지 않습니다 |

**고정 설치(`PERMANENT`)** 는 로비·스폰에 두는 상자용입니다. 소멸도 재생성도 없으므로 무한 획득을 막기 위해 **열쇠나 소모 금액이 반드시 있어야** 하며, 둘 다 없으면 아예 열리지 않습니다. 항상 상자 창으로 열리고, 창을 닫으면 남은 아이템이 바닥이 아니라 **인벤토리로 들어갑니다**. 1인 제한(아래)과 함께 쓰는 것을 전제로 합니다.

### 오픈 방식

| 방식 | 동작 |
|---|---|
| `DIRECT` | 아이템이 인벤토리로 바로 들어옵니다 |
| `GUI` | 상자 창이 열리고 직접 꺼냅니다 (기본값) |
| `DROP` | 상자가 있던 자리에 아이템이 쏟아집니다 — 주변에 도착한 사람들이 같이 주울 수 있습니다 |

맵에 생성된 상자는 어느 방식이든 한 번 열리면 아이템을 안 꺼내도 사라집니다. 고정 설치 상자만 예외로 그 자리에 남습니다.

### 1인 제한 · 숨김 상자

- **1인 재오픈 대기시간** — 같은 유저가 같은 상자를 다시 열기까지의 시간
- **1인 최대 오픈 횟수** — 한 유저가 열 수 있는 횟수 (0 = 무제한)
- **오픈 횟수 초기화 주기** — 위 횟수가 다시 채워지는 주기 (0 = 초기화 없음, 기본값)
- **검색 허용 / 추적 허용** — 끄면 `/urb search` 목록과 나침반 추적에서 빠집니다

초기화 주기를 `0` 으로 두면 **평생 제한**이고, `1d` 로 두면 **하루에 N번**이 됩니다. 주기는 서버 시계가 아니라 **그 유저가 상자를 처음 연 시각**부터 셉니다 — 자정 직전에 도착한 사람이 2초짜리 창을 받는 일이 없도록 하기 위해서입니다. 제한에 걸린 플레이어에게는 남은 시간까지 함께 안내됩니다.

다섯을 조합하면 "로비 어딘가에 조용히 숨겨두고, 한 사람당 하루 한 번만 먹을 수 있는" 찾기 컨텐츠가 됩니다. 기록은 `data/opens.yml` 에 저장되어 재시작해도 유지되고, GUI 에서 상자별로 초기화할 수 있습니다.

## 연출

### 상자 주변 (파티클)

15종 + 사용 안 함. 1초에 한 번, **플레이어가 있는 월드의 로드된 청크에서만** 그려집니다.

`SPARKLE` `FLAME_RING` `SOUL_RISE` `ENCHANT_SWIRL` `PORTAL_VORTEX` `END_ROD_BEAM` `HEART_FLOAT` `NOTE_POP` `CLOUD_HALO` `GOLD_DUST` `SPIRAL` `FOUNTAIN` `CRIT_BURST` `SPARK_RING` `RAINBOW`

`SPIRAL` 은 이중 나선, `SPARK_RING` 은 이중 전기 고리, `RAINBOW` 는 높이에 따라 색이 변하는 기둥입니다.

### 상자를 열 때 (오픈 연출)

| 값 | 동작 |
|---|---|
| `NONE` | 연출 없이 바로 지급 |
| `ROULETTE` | 후보 아이템이 빠르게 돌다가 점점 느려지며 결과에 멈춥니다 |
| `REVEAL` | 보상이 하나씩 차례로 등장하고, 소리 음정이 점점 올라갑니다 |

> **추첨은 연출이 시작되기 전에 이미 끝나 있습니다.** 연출은 보여주는 방식만 바꿉니다. 그래서 도중에 창을 닫아도, 렉이 걸려도, 접속이 끊겨도 결과가 달라지지 않습니다. 창을 일찍 닫으면 그 자리에서 즉시 지급되고, 접속이 끊기면 상자가 있던 자리에 떨어지며, 연출 도중 서버가 종료되어도 지급이 먼저 처리된 뒤에 저장됩니다.

### 보상을 받을 때 (획득 연출)

| 값 | 동작 |
|---|---|
| `NONE` | 없음 |
| `TOTEM` | 불사의 토템 연출과 소리 |
| `FIREWORK` | 상자 자리에서 폭죽이 터집니다 (**피해 없음**) |
| `LIGHTNING` | 번개 **모양만** 내려칩니다 (**피해·화재·몹 변이 없음**) |
| `FANFARE` | 종소리 아르페지오 |
| `BEAM` | 하늘로 솟는 빛기둥 |

⑦ 화면에서 연출을 바꾸면 그 자리에서 미리보기가 재생됩니다. 파티클·오픈 연출·획득 연출 모두 **좌클릭 = 다음, 우클릭 = 이전, Shift+클릭 = 끄기** 입니다. 생성 방식과 오픈 방식도 같은 방식으로 앞뒤로 넘길 수 있습니다.

### 그 외

- **홀로그램** — 상자 위에 이름과 남은 시간. 서버에 저장되지 않는 표시용 엔티티라 크래시가 나도 찌꺼기가 남지 않습니다
- **추적 안내 파티클** — `/urb search` 에서 상자를 고르면 그 방향으로 파티클이 이어집니다 (추적한 본인에게만 보입니다)

## 보상 시뮬레이션 (어드민 전용)

상자 관리 → **⑧ 보상 시뮬레이션**, 또는 `/urb simulate <상자>`. 시행 횟수를 입력하면 **실제 오픈과 똑같은 추첨기**를 그만큼 돌려 결과를 GUI로 보여줍니다.

보상마다:

| 항목 | 의미 |
|---|---|
| 설정 확률 / 실제 출현 / 차이 | 아래 설명 참고 |
| 1회당 평균 · 100회당 총량 | 수량 기준 배출량 |
| 명령어 실행 횟수 | 명령어 보상이 몇 번 발동하는지 |
| ⚠ 표시 | 원본 플러그인이 없어 **실제로는 안 나오는** 보상 |

하단 4개 패널:

- **개수 분포** — 1개 몇 %, 2개 몇 %, 평균 몇 개 (티어를 쓰면 풀별 내역도 함께)
- **진단** — 아래 설명
- **산출량 예측** — 생성 주기를 곱해 "하루에 아이템 N개, 전체공지 K회"
- **비용 분석** — 열쇠/금액 1회·100회 비용, 아이템 1개당 비용

### 시뮬레이션 없이도 보이는 예측

상자 관리 → **④ 내용물 개수** 와 **⑨ 보상 티어** 는 시뮬레이션을 돌리지 않아도 **예상 개수 분포를 즉시** 보여줍니다. 각 보상이 독립 시행이라 분포를 포아송 이항분포로 정확히 계산할 수 있고, 티어가 여러 개면 그 분포들을 합성곱으로 합칩니다. 보상 54종이라도 수천 번 연산이라 클릭할 때마다 갱신됩니다.

특히 두 가지 함정을 명시적으로 경고합니다.

```
현재: 1 ~ 5개
실질 최대: 3개  ⚠ 등록된 보상이 3종뿐입니다

예상 개수 분포
  1개 50%   ||||||||||
  2개 37.5% |||||||
  3개 12.5% ||
```

- **최대값이 보상 수보다 크면** 조용히 잘립니다. 보상 3종에 최대 5개를 넣어도 3개가 한계입니다.
- **최대값이 나올 확률이 낮으면** 알려줍니다. 50% 보상 3종에 최대 3개면 3개가 나오는 건 8번에 한 번입니다.

### 설정 확률과 실제 출현률은 다릅니다

이건 버그가 아니라 추첨 규칙의 결과입니다.

- 당첨된 보상이 **최대 개수보다 많으면 잘려나가** → 실제 출현률이 설정보다 **낮아집니다**
- 아무것도 당첨되지 않으면 **최소 보장이 발동** → 일부 보상이 설정보다 **높아집니다**

25%로 설정한 아이템이 실제로 18%인 것이 정상입니다. **진단 패널**이 둘 중 무엇이 작용했는지 알려줍니다.

- `최대 개수로 잘림` 이 70% 이상이면 → 개별 확률을 바꿔도 체감이 안 바뀝니다. 최대 개수를 늘리세요.
- `최소 보장 발동` 이 50% 이상이면 → 확률이 전반적으로 너무 낮아 사실상 가중치 뽑기입니다.
- `전체 공지` 가 5% 이상이면 → 20번에 한 번 채팅이 도배됩니다.

### 확률 일괄 조정

① 아이템 설정의 **[확률 일괄 조정]** 은 두 가지를 합니다.

- **비율 유지 조정 (좌클릭)** — 목표 확률 합을 입력하면 지금의 희귀도 차이는 그대로 두고 전체 합만 맞춥니다. "상자가 너무 후하다" 는 대부분 이쪽입니다.
- **균등 분배 (우클릭)** — 모든 보상을 같은 확률로 맞춥니다. 처음부터 다시 잡을 때만 쓰세요.

확률은 0.01 ~ 100 으로 제한되므로 목표에 정확히 도달하지 못할 수 있고, 그래서 조정 후 **실제로 도달한 합계**를 함께 알려줍니다.

### 정확도와 시드

시행 횟수 상한은 `config.yml` 의 `simulation.max-iterations` (기본 1000만). 확률 0.01% 아이템도 1000만 회면 오차 ±3% 수준입니다. 진행 상황은 보스바로 표시됩니다.

`횟수 시드` 형식(`100000 42`)으로 입력하면 **같은 시드로 재현**됩니다. 확률을 하나 바꾸고 같은 시드로 다시 돌리면, 차이가 RNG 노이즈가 아니라 수정 때문임이 확실해집니다.

시뮬레이션은 시작할 때 보상 테이블과 티어 설정을 스냅샷으로 떠서 별도 스레드에서 돌기 때문에, 도중에 GUI로 확률을 고쳐도 결과가 섞이지 않고 서버도 멈추지 않습니다.

## 통계 · 오픈 기록 · 랭킹

시뮬레이터가 **"어떻게 되어야 하는가"** 라면, 통계는 **"실제로 어떻게 되었는가"** 입니다. 둘을 나란히 보면 문제의 성격이 갈립니다 — 양쪽 모두에서 낮으면 설정 문제이고, 통계에서만 어긋나면 표본이 적거나 아이템을 못 불러온 것입니다.

- **상자 관리 → 통계 · 오픈 기록** — 보상별 설정 확률 / 실제 출현률 / 차이(%p) / 누적 지급량, 오픈당 실제 개수와 이론 개수 비교
- **오픈 기록** (`/urb log`) — 최근 오픈을 시간순으로. 누가, 어떤 상자를, 어디서 열어 무엇을 받았는지 전부 남습니다. `/urb notice` 가 **공지 대상 아이템만** 보여주는 것과 달리 이쪽은 **모든 오픈**을 기록하므로, "왜 나는 그게 안 나왔냐" 는 문의에 답할 수 있습니다
- **오픈 랭킹** (`/urb ranking`) — 가장 많이 연 플레이어 순위. 유저도 볼 수 있습니다

기록은 `data/stats.yml` 에 저장되어 재시작해도 유지되고, 보관 개수는 `stats.log-size` (기본 100) 로 조절합니다. 표본이 50회 미만이면 "편차가 큽니다" 라고 명시해 줍니다.

## 청크 대기열

랜덤으로 뽑힌 좌표의 청크가 로드되어 있지 않으면, **공지는 즉시 나가고** 실제 블록은 대기열에 들어갑니다. 누군가 그 좌표로 이동해 청크가 자연스럽게 열리면 그때 나타납니다. 청크를 강제로 생성하지 않기 때문에 넓은 영역을 지정해도 서버가 멈추지 않습니다.

대기열에 남을 수 있는 최대 시간은 `spawn.pending-max-age`(기본 2일)입니다.

## 재시작

생성된 상자는 **재시작 후에도 그대로 남고**, 소멸 시간이 지나야 사라집니다. 소멸 시각은 절대 시간으로 저장되므로 서버가 꺼져 있는 동안 만료된 상자는 다음 기동 때 정리됩니다. 종료 시 전부 치우고 싶으면 `shutdown.cleanup-all: true` 로 두세요.

## 상자 블록

블록 엔티티가 아니어도 됩니다. `STONE` 으로 지정하면 돌처럼 보이지만 클릭하면 상자 창이 열립니다. 상자는 채굴·폭발·피스톤·용암·불로 파괴되지 않으며, 사라질 때 원래 있던 블록이 정확히 복원됩니다.

## 아이템 저장 방식

보상은 기본적으로 **참조**로 저장됩니다 (`minecraft:diamond`, `mmoitems:SWORD:EXCALIBUR`, `itemsadder:ruby`, `nexo:ruby`, `oraxen:ruby`, `ecoitems:ruby`). 지급할 때마다 원본 정의대로 새로 만들기 때문에

- MMOItems 등에서 아이템을 수정하면 상자 보상에도 바로 반영되고,
- 새로 발급한 같은 아이템과 인벤토리에서 정상적으로 겹칩니다.

이름·로어·인챈트를 손수 붙인 바닐라 아이템처럼 참조로 표현할 수 없는 것은 **스냅샷**으로 저장됩니다. 보상 상세 설정에서 언제든 전환할 수 있습니다.

GUI 아이콘은 아이템 **원래 로어를 그대로 두고** 그 아래에 확률·수량을 덧붙입니다. MMOItems 무기의 스탯이나 커스텀 아이템 설명이 `/urb info` 확률표에서도 그대로 보입니다. 원본 플러그인이 꺼져 있어 아이템을 만들 수 없으면 아이콘에 `⚠ 원본 아이템을 불러올 수 없습니다` 가 표시되므로, 평범한 바닐라 아이템으로 착각할 일이 없습니다.

## 설정 파일

```
plugins/inmc-urb/
├─ config.yml         기본값 · 대기열 · 검색 · 통계 · 디스코드
├─ messages.yml       모든 메시지 (MiniMessage)
├─ boxes/<이름>.yml   상자별 설정 (GUI 가 자동으로 씁니다)
└─ data/
   ├─ state.yml       생성된 상자 · 대기열 · 복원 대기
   ├─ notice.yml      당첨 공지 기록
   ├─ opens.yml       유저별 오픈 기록 (1인 제한용)
   └─ stats.yml       통계 · 오픈 기록 · 랭킹
```

모든 파일 입출력은 전용 워커 스레드에서 처리되고, 반복 작업은 **1초 주기 태스크 하나뿐**입니다. 오픈 연출은 반복 태스크가 아니라 한 번짜리 지연 작업을 이어 붙여 만듭니다.

## 플레이스홀더

메시지 안에서 사용:

`{상자이름}` `{플레이어네임}` `{좌표}` `{열쇠이름}` `{필요한돈}` `{아이템}` `{world}` `{x}` `{y}` `{z}` `{시간}` `{개수}` `{거리}` `{돈보유}` `{새이름}`

영문 별칭도 됩니다: `{box}` `{player}` `{location}` `{key}` `{money}` `{item}`

PlaceholderAPI 가 있으면 메시지 안의 `%papi_...%` 도 처리되고, 반대로 다음 확장이 등록됩니다.

| 플레이스홀더 | 값 |
|---|---|
| `%urb_spawned_total%` | 현재 배치된 상자 수 |
| `%urb_pending_total%` | 대기열에 있는 상자 수 |
| `%urb_box_count%` | 등록된 상자 종류 수 |
| `%urb_spawned_<상자>%` | 그 상자의 현재 개수 (대기 포함) |
| `%urb_nearest%` / `%urb_nearest_box%` / `%urb_nearest_distance%` | 가장 가까운 상자 |
| `%urb_search_cooldown%` | 남은 검색 대기시간 |
| `%urb_opens_total%` | 전체 누적 오픈 수 |
| `%urb_opens_<상자>%` | 그 상자의 누적 오픈 수 |
| `%urb_my_opens%` / `%urb_my_rank%` | 내 오픈 수 / 내 순위 |
| `%urb_remaining_<상자>%` | 내가 그 상자를 더 열 수 있는 횟수 (무제한이면 `-`) |
| `%urb_top_name_<n>%` / `%urb_top_opens_<n>%` | n위 플레이어 이름 / 오픈 수 |
| `%urb_next_<상자>%` | 다음 자동 생성까지 남은 시간 |
| `%urb_schedule_<상자>%` | 생성 시간대 요약 (예: `주말 20:00~23:00`) |

상자 이름에 공백이 있으면 `_` 로 대신 써도 인식합니다.

## 디스코드 알림

플러그인 설치가 필요 없습니다. 채널 설정 → 연동 → 웹후크에서 URL 을 만들어 `config.yml` 에 넣으면 됩니다. 비워두면 관련 기능이 전부 꺼집니다.

훅은 세 단계로 정해집니다 — **상자별 설정 → 종류별 주소 → 공통 주소** 순으로 먼저 채워진 값을 씁니다.

| 설정 | 용도 |
|---|---|
| `discord.webhook-url` | 아래 두 개가 비었을 때 쓰이는 공통 주소 |
| `discord.spawn.webhook-url` | 상자 등장 알림 전용 (예: 트레저헌터 채널) |
| `discord.reward.webhook-url` | 당첨 공지 전용 (예: 전체 공지 채널) |
| 상자 GUI → 연출·제한 | 그 상자만 다른 채널로 보내기 |

덕분에 "스폰 알림은 헌터 채널로, 대박 당첨은 공지 채널로" 같은 분리가 가능합니다.

## 기존 UltimateRandomBox 에서 넘어올 때

구조가 달라 자동 마이그레이션은 없습니다. `boxes/example.yml` 을 참고해 다시 설정하거나 `/urb` GUI 로 만들면 됩니다. 대응표:

| 기존 | 지금 |
